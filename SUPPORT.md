# CF WordPress Plugin Support

These plugins are free professional utilities. Support is best-effort unless there is an existing client relationship or a separate support agreement.

## Bug Reports

Bug reports are welcome when they include enough detail to reproduce the issue.

Useful bug reports include:

- Plugin name and version.
- WordPress version.
- PHP version.
- Active theme.
- Relevant active plugins, especially SEO, cache, media, schema, security, and editor plugins.
- Whether the site is single-site or multisite.
- Exact steps to reproduce.
- Expected behavior.
- Actual behavior.
- Screenshots, browser console errors, PHP errors, logs, or exported diagnostics when available.

## Triage Priority

Priority order:

1. Security issues and data-loss risks.
2. Reproducible bugs affecting current client/internal use.
3. Reproducible public bugs with clear steps and environment details.
4. Compatibility issues with major WordPress, PHP, SEO, cache, media, and editor stacks.
5. Feature requests.

## Plugin UI Policy

Each plugin may expose a quiet "Report a bug" link from its settings/admin screen when the URL is stable.

The bug-report affordance should be small and WordPress-native. Do not add upsell boxes, onboarding modals, banners, email gates, or suite marketing to plugin screens.

## Current Baseline

Target baseline for active plugin work:

- WordPress `6.2+`
- PHP `8.0+`

If a bug is reported below that baseline, document it, but do not treat support as guaranteed.
