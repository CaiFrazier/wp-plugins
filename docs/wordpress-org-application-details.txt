CF Media Optimizer 3.0.4
Additional details

I maintain this plugin under Cai Frazier using the WordPress.org username caifrazier. This submission is version 3.0.4, requires WordPress 6.2+ and PHP 8.1+, and is GPL-2.0-or-later.

CF Media Optimizer creates WebP and optional AVIF variants of JPEG/PNG attachments and serves them through picture markup with the original image as fallback. It installs independently of CF Media Manager. Conversion runs locally, with background work using Action Scheduler when available or WP-Cron.

The server must provide WebP encoding through GD or Imagick. AVIF is optional and depends on the host's encoder. The plugin preserves original images and tracks the generated files it owns. An authorized administrator can explicitly run the live-page verifier, which requests the chosen public URL and sends ordinary HTTP request information to that host. No telemetry is sent to the author, and no author-operated optimization service is used.

The ZIP includes production dependencies and license notices. It is GPL-2.0-or-later. Two local AVIF-specific PHPUnit checks were skipped because the local encoder was unavailable; the package passed Plugin Check. These checks do not establish AVIF support on every host.

Additional details

I maintain this plugin under Cai Frazier using the WordPress.org username caifrazier. This submission is version 1.2.2, requires WordPress 6.2+ and PHP 8.1+, and is GPL-2.0-or-later.

CF Chunked Upload splits large files into browser-side chunks and assembles them on the server. It integrates with the Media Library and provides a separate Tools > Import Large File screen. It works within per-request host limits; it does not change PHP configuration or remove disk-space limits.

Files and temporary chunks stay on the site's server. Upload sessions are tied to the submitting user, chunks are checked with SHA-256, and quota/disk-space checks bound storage use. Assembly and cleanup need a working background runner through WP-Cron or Action Scheduler when available. The readme documents the additional temporary-directory deny rule needed for Nginx. Imported files are retained after deactivation or uninstall. Plugin/theme ZIP installation is outside this version's scope.

No external service or telemetry is used. The ZIP includes production dependencies, GPL-2.0-or-later licensing, and third-party notices.

CF QR Redirect 1.3.2
Additional details

I maintain this plugin under Cai Frazier using the WordPress.org username caifrazier. This submission is version 1.3.2, requires WordPress 6.2+ and PHP 8.1+, and is GPL-2.0-or-later.

CF QR Redirect creates short URLs on the site's own domain, generates QR artwork in the browser, and manages redirect destinations. qrcode.js and JSZip are bundled locally with their license notices. QR/redirect management is restricted by plugin-prefixed WordPress capabilities.

External HTTP(S) destinations are an intentional administrator-controlled feature. Saved destinations are validated; public visitors do not supply an arbitrary destination parameter. The default UTM mode adds attribution parameters and redirects without loading a plugin analytics script. Optional intermediate-page mode loads Google's gtag.js and sends a qr_redirect event to the owner's configured GA4 property. Google receives normal request information and may use cookies. This mode does not inherit the theme's consent manager, so the readme documents the need to establish visitor consent before using it. Google terms/privacy links are provided in the readme.

Hit counts, destination-change audit records, and captured 404 data are stored locally with documented retention. No telemetry is sent to the plugin author. The plugin is GPL-2.0-or-later and requires PHP 8.1; the stale 8.0 readme-body requirement has been corrected.

Schema Override Manager 1.0.2
Additional details

I maintain this plugin under Cai Frazier using the WordPress.org username caifrazier. This submission is version 1.0.2, requires WordPress 6.2+ and PHP 8.1+, and is GPL-2.0-or-later.

Schema Override Manager lets site administrators configure site identity schema and post-type templates, and lets authorized editors manage per-post JSON-LD overrides. It can integrate with Yoast SEO or Rank Math, but neither is required.

Settings and overrides stay in the WordPress database. Configured JSON-LD is published on the site for visitors and search engines. The live-schema inspector fetches the site's own post permalink only when an authorized user requests it. Schema.org URLs identify the vocabulary; they are not an external API dependency. Optional diagnostic logs stay under uploads, and no author telemetry is used.

Theme/other JSON-LD suppression is disabled by default. When explicitly enabled and matched by a suppression rule, its output buffering is limited to wp_head. Saved schema is sanitized with payload limits. Compatibility-hook annotations document the externally owned Yoast/Rank Math hooks. The ZIP includes production dependencies, GPL-2.0-or-later licensing, and third-party notices.
